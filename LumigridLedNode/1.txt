Next, implement the **logical pixel mapper, parallel-output abstraction, Art-Net frame conversion, diagnostics, and automated tests**. This is the point where the factory firmware becomes an actual LumiGrid controller rather than a set of individual output tests.

Use ESP-IDF’s Unity-based test support for pure mapping/config/protocol tests, and add the Task Watchdog to the render and output tasks so a stalled frame path is detected rather than silently leaving an installation in an undefined state. [docs.espressif](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-guides/unit-tests.html)

## Logical canvas

Treat every physical output as a configurable view into one logical canvas. Art-Net, DDP, local effects, MQTT scenes, and the UI all write to that one canvas; only the mapper knows how it becomes eight physical strips and PWM groups.

```text
Logical canvas: [pixel 0 ................................ pixel N]
                     |
                     v
              PixelMapper
       ┌─────────────┼─────────────┐
       v             v             v
    Lane 0        Lane 1        Lane 7
  physical LEDs physical LEDs physical LEDs

                     |
                     v
                PwmMapper
      PCA channel 0 ................ PCA channel 15
```

This lets one installation use 8 independent strips, while another can make all eight connectors part of one continuous sign, without changing firmware.

## Frame types

Keep the generic render frame separate from hardware-specific objects.

```cpp
// components/output/include/lg_frame.hpp
#pragma once
#include <array>
#include <cstddef>
#include <cstdint>

namespace lg {

constexpr size_t kMaxPixelsPerLane = 1000;
constexpr size_t kPixelLaneCount = 8;
constexpr size_t kMaxLogicalPixels = kMaxPixelsPerLane * kPixelLaneCount;
constexpr size_t kPwmChannelCount = 16;

struct Rgb {
    uint8_t r = 0;
    uint8_t g = 0;
    uint8_t b = 0;
};

struct Rgbw {
    uint8_t r = 0;
    uint8_t g = 0;
    uint8_t b = 0;
    uint8_t w = 0;
};

struct LogicalFrame {
    std::array<Rgb, kMaxLogicalPixels> pixels{};
    std::array<uint16_t, kPwmChannelCount> pwm{};
    uint32_t sequence = 0;
    uint32_t timestamp_ms = 0;
    uint16_t pixel_count = 0;
};

struct PhysicalFrame {
    std::array<std::array<Rgb, kMaxPixelsPerLane>, kPixelLaneCount> lanes{};
    std::array<uint16_t, kPwmChannelCount> pwm{};
    uint32_t sequence = 0;
};

} // namespace lg
```

For RGBW strips, either make the entire logical renderer RGBA/RGBW now or explicitly restrict the first factory release to RGB. Do **not** silently discard white data when a lane is configured as RGBW. The clean route is to define `Color16` or `Rgbw` as the canonical pixel representation before adding DDP and RGBW support.

## Pixel mapper

The mapper applies lane configuration, reverse direction, per-lane brightness, colour order, gamma correction, and current limiting. Keep raw protocol bytes out of this layer.

```cpp
// components/output/include/lg_pixel_mapper.hpp
#pragma once
#include "lg_config.hpp"
#include "lg_frame.hpp"

namespace lg {

class PixelMapper {
public:
    explicit PixelMapper(const NodeConfig& config);

    void update_config(const NodeConfig& config);
    void map(const LogicalFrame& source, PhysicalFrame& target) const;

private:
    static uint8_t gamma8(uint8_t value);
    static Rgb scale(Rgb color, uint8_t brightness);
    static Rgb reorder(Rgb color, PixelOrder order);

    NodeConfig config_;
};

} // namespace lg
```

```cpp
// components/output/lg_pixel_mapper.cpp
#include "lg_pixel_mapper.hpp"
#include <algorithm>

namespace lg {

PixelMapper::PixelMapper(const NodeConfig& config) : config_(config) {}

void PixelMapper::update_config(const NodeConfig& config) {
    config_ = config;
}

Rgb PixelMapper::scale(Rgb c, uint8_t brightness) {
    return {
        .r = static_cast<uint8_t>((uint16_t(c.r) * brightness + 127) / 255),
        .g = static_cast<uint8_t>((uint16_t(c.g) * brightness + 127) / 255),
        .b = static_cast<uint8_t>((uint16_t(c.b) * brightness + 127) / 255)
    };
}

Rgb PixelMapper::reorder(Rgb c, PixelOrder order) {
    switch (order) {
        case PixelOrder::RGB: return c;
        case PixelOrder::GRB: return {.r = c.g, .g = c.r, .b = c.b};
        default:              return c;
    }
}

uint8_t PixelMapper::gamma8(uint8_t value) {
    // Replace this with a generated 256-entry LUT in production.
    return static_cast<uint8_t>(
        (uint32_t(value) * value + 255U) / 255U
    );
}

void PixelMapper::map(const LogicalFrame& source, PhysicalFrame& target) const {
    target.sequence = source.sequence;
    target.pwm = source.pwm;

    for (size_t lane_index = 0; lane_index < kPixelLaneCount; ++lane_index) {
        const auto& lane = config_.lanes[lane_index];
        if (!lane.enabled || lane.pixel_count == 0) continue;

        for (uint16_t physical = 0; physical < lane.pixel_count; ++physical) {
            const uint16_t source_index =
                lane.logical_start +
                (lane.reversed ? lane.pixel_count - 1 - physical : physical);

            if (source_index >= source.pixel_count) continue;

            Rgb pixel = scale(source.pixels[source_index], lane.brightness);
            pixel = {
                .r = gamma8(pixel.r),
                .g = gamma8(pixel.g),
                .b = gamma8(pixel.b)
            };

            target.lanes[lane_index][physical] = reorder(pixel, lane.order);
        }
    }
}

} // namespace lg
```

The `reorder()` example is intentionally simplified. In a production pixel library, it is normally better to keep RGB values in canonical order and let the output encoder emit GRB/RGB/RGBW byte order. That prevents colour calculations from accidentally operating on already reordered components.

## Gamma and brightness

Generate a real gamma LUT rather than calculate gamma within the 60 FPS loop. The mapper should only perform array lookups:

```python
# tools/generate_gamma.py
import math

gamma = 2.2
values = [
    round((index / 255.0) ** gamma * 255.0)
    for index in range(256)
]

with open("components/output/include/lg_gamma_lut.hpp", "w") as file:
    file.write("#pragma once\n#include <array>\n#include <cstdint>\n\n")
    file.write("namespace lg {\n")
    file.write("constexpr std::array<uint8_t, 256> kGamma22 = {\n    ")

    for index, value in enumerate(values):
        file.write(str(value))
        file.write(", " if index < 255 else "")

        if (index + 1) % 16 == 0 and index != 255:
            file.write("\n    ")

    file.write("\n};\n} // namespace lg\n")
```

Run this in CI when the gamma parameter changes, then commit the generated header. Do not make field calibration depend on Python existing on the device build host.

## Art-Net-to-frame mapping

An Art-Net universe contains up to 512 DMX slots. For RGB pixels, each pixel consumes three slots; a universe therefore carries 170 complete RGB pixels plus two spare channels.

```text
Universe 0:
  DMX 001 -> logical pixel 0 red
  DMX 002 -> logical pixel 0 green
  DMX 003 -> logical pixel 0 blue
  ...
  DMX 510 -> logical pixel 169 blue

Universe 1:
  DMX 001 -> logical pixel 170 red
```

Implement a protocol converter rather than placing this logic in `ArtnetReceiver`.

```cpp
// components/protocols/include/lg_artnet_mapper.hpp
#pragma once
#include <cstddef>
#include <cstdint>
#include "lg_frame.hpp"

namespace lg {

class ArtnetMapper {
public:
    explicit ArtnetMapper(uint16_t first_universe);

    void clear();
    void apply_universe(uint16_t universe,
                        const uint8_t* dmx,
                        size_t length);

    const LogicalFrame& staging_frame() const;
    LogicalFrame take_frame(uint32_t sequence, uint32_t timestamp_ms);

private:
    uint16_t first_universe_;
    LogicalFrame frame_{};
};

} // namespace lg
```

```cpp
// components/protocols/lg_artnet_mapper.cpp
#include "lg_artnet_mapper.hpp"
#include <algorithm>

namespace lg {

ArtnetMapper::ArtnetMapper(uint16_t first_universe)
    : first_universe_(first_universe) {}

void ArtnetMapper::clear() {
    frame_ = {};
}

void ArtnetMapper::apply_universe(uint16_t universe,
                                   const uint8_t* dmx,
                                   size_t length) {
    if (universe < first_universe_ || dmx == nullptr) return;

    const size_t universe_offset =
        static_cast<size_t>(universe - first_universe_) * 170U;

    const size_t usable = std::min(length, size_t{510});
    const size_t pixel_count = usable / 3U;

    for (size_t pixel = 0; pixel < pixel_count; ++pixel) {
        const size_t target = universe_offset + pixel;
        if (target >= kMaxLogicalPixels) break;

        const size_t source = pixel * 3U;
        frame_.pixels[target] = {
            .r = dmx[source],
            .g = dmx[source + 1],
            .b = dmx[source + 2]
        };

        frame_.pixel_count = std::max(
            frame_.pixel_count,
            static_cast<uint16_t>(target + 1)
        );
    }
}

const LogicalFrame& ArtnetMapper::staging_frame() const {
    return frame_;
}

LogicalFrame ArtnetMapper::take_frame(uint32_t sequence,
                                      uint32_t timestamp_ms) {
    frame_.sequence = sequence;
    frame_.timestamp_ms = timestamp_ms;
    return frame_;
}

} // namespace lg
```

For fixture PWM channels, reserve configurable DMX slot ranges or dedicated Art-Net universes. Do not automatically append PCA output levels directly after your last pixel unless that mapping is clear in the saved configuration.

## Output task

Use a queue of depth two. If the network receives frames faster than the device can safely show them, discard the oldest pending one and retain the newest. Live lighting must remain current; it should not become delayed.

```cpp
// components/output/lg_render_pipeline.cpp
namespace lg {
namespace {
QueueHandle_t s_ready_frames = nullptr;
}

esp_err_t RenderPipeline::start() {
    s_ready_frames = xQueueCreate(2, sizeof(LogicalFrame));
    if (s_ready_frames == nullptr) return ESP_ERR_NO_MEM;

    return xTaskCreatePinnedToCore(
        output_task_entry,
        "lg_output",
        8192,
        this,
        8,
        &output_task_,
        1
    ) == pdPASS ? ESP_OK : ESP_FAIL;
}

void RenderPipeline::submit_latest(const LogicalFrame& frame) {
    if (xQueueSend(s_ready_frames, &frame, 0) == pdPASS) return;

    LogicalFrame discarded;
    xQueueReceive(s_ready_frames, &discarded, 0);
    xQueueSend(s_ready_frames, &frame, 0);
    ++metrics_.dropped_frames;
}

void RenderPipeline::output_task_entry(void* argument) {
    static_cast<RenderPipeline*>(argument)->output_task();
}

void RenderPipeline::output_task() {
    LogicalFrame logical;
    PhysicalFrame physical;

    esp_task_wdt_add(nullptr);

    for (;;) {
        if (xQueueReceive(s_ready_frames, &logical, portMAX_DELAY) == pdPASS) {
            mapper_.map(logical, physical);
            output_.commit(physical);
            metrics_.last_sequence = logical.sequence;
        }

        esp_task_wdt_reset();
    }
}
} // namespace lg
```

The Task Watchdog is specifically intended to detect tasks that fail to yield or run longer than their configured timeout. [docs.espressif](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/wdts.html)

Keep the output task on Core 1. Put Wi-Fi, UDP socket work, MQTT, API work, NVS access, and filesystem work on Core 0 or unpinned. Do not call NVS, LittleFS, JSON parsing, or logging at high volume from the output task.

## Output-health watchdog

A FreeRTOS task watchdog only tells you a task stopped running. Add a domain-specific output watchdog to guarantee shutdown if the expected output cadence fails.

```cpp
class OutputHealth {
public:
    void mark_frame_committed(uint32_t now_ms) {
        last_frame_ms_ = now_ms;
    }

    bool frame_deadline_missed(uint32_t now_ms) const {
        return outputs_enabled_ && (now_ms - last_frame_ms_ > 250);
    }

    void set_outputs_enabled(bool enabled) {
        outputs_enabled_ = enabled;
    }

private:
    uint32_t last_frame_ms_ = 0;
    bool outputs_enabled_ = false;
};
```

A diagnostics task should poll it every 50 ms. If it expires, it must:

1. Set PCA `OE#` high.
2. Clear and transmit a black pixel frame where the transport permits it.
3. Latch a `OutputDeadlineMissed` fault.
4. Stop the active protocol source.
5. Require an explicit authenticated recovery command.

## Hardware test patterns

Expand basic solid-colour tests into useful bench patterns.

| Test | Parameters | Detects |
|---|---|---|
| Lane solid | Lane, RGB, brightness, timeout | Connector-to-lane mapping, RGB channel order |
| Lane chase | Lane, period, brightness, timeout | Pixel count, direction, intermittent data |
| Lane gradient | Lane, colour A/B, timeout | Data errors and pixel ordering |
| All-lanes identity | Eight fixed unique colours | Lane swaps, level-shifter routing faults |
| PWM level | Channel, duty, timeout | MOSFET / fixture channel wiring |
| PWM ramp | Channel/group, min/max/period | Inversion, flicker, dead zones |
| PWM walking | One channel at a time | Crosstalk and group mapping errors |
| Burn-in | Configured brightness, duration | Heat, power supply, Wi-Fi stability, frame drops |
| Emergency blackout | No parameters | OE and output safe-state verification |

A factory board should not be allowed to execute burn-in from a remote MQTT command. Make it a locally authenticated API action with a physical jumper, button confirmation, or a short-lived service token.

## Tests before hardware

The protocol parser, configuration validator, Art-Net mapper, pixel mapper, source-priority logic, and timeout logic should compile and run without a physical ESP32. ESP-IDF’s built-in test support is based on Unity and supports running selected test cases on target hardware; keep pure code isolated enough to also compile under your desktop CI toolchain. [docs.espressif](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-guides/unit-tests.html)

```cpp
// test/test_artnet_mapper.cpp
#include "unity.h"
#include "lg_artnet_mapper.hpp"

TEST_CASE("Art-Net universe maps first RGB pixels", "[artnet]") {
    lg::ArtnetMapper mapper(0);
    const uint8_t universe[] = {
        255, 0, 0,
        0, 255, 0,
        0, 0, 255
    };

    mapper.apply_universe(0, universe, sizeof(universe));
    const auto& frame = mapper.staging_frame();

    TEST_ASSERT_EQUAL_UINT8(255, frame.pixels[0].r);
    TEST_ASSERT_EQUAL_UINT8(255, frame.pixels [docs.espressif](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-guides/unit-tests.html).g);
    TEST_ASSERT_EQUAL_UINT8(255, frame.pixels [docs.espressif](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/system/wdts.html).b);
    TEST_ASSERT_EQUAL_UINT16(3, frame.pixel_count);
}
```

Minimum test list:

```text
[ ] Invalid PWM overlap is rejected
[ ] PWM channel 16 is rejected
[ ] Disabled lane emits black physical pixels
[ ] Reversed lane maps first logical pixel to final physical LED
[ ] Brightness 0 emits black
[ ] Art-Net packet shorter than 3 bytes maps no pixel
[ ] Art-Net universe offset starts at logical pixel 170
[ ] ArtSync atomically commits staging frame
[ ] Newest-frame queue discards stale frame
[ ] Source timeout returns output to safe state
[ ] Hardware test always finishes with blackout
[ ] Config serialization excludes credentials
```

## Web assets and reports

Use LittleFS for static web assets and factory reports. The ESP-IDF LittleFS component is designed as a small fail-safe microcontroller filesystem, and its build integration can generate a filesystem image from a directory with `littlefs_create_partition_image`. [components.espressif](https://components.espressif.com/components/joltwallet/littlefs/versions/1.5.3/readme?language=en)

```cmake
# main/CMakeLists.txt
idf_component_register(
    SRCS "main.cpp"
    INCLUDE_DIRS "."
    REQUIRES board config output protocols diagnostics api
)

littlefs_create_partition_image(
    littlefs
    "${CMAKE_CURRENT_LIST_DIR}/../web/dist"
    FLASH_IN_PROJECT
)
```

Use a write-once report name based on serial number and UTC time:

```text
/reports/LGN-260715-0001_2026-07-15T16-22-06Z.json
```

Do not log every Art-Net packet or frame commit to LittleFS; flash wear and write latency are unacceptable. Persist only configuration, crash summaries, explicit factory reports, and concise fault snapshots.
