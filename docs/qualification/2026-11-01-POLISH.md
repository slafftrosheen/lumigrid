# Hardware, playback and operator continuity — 2026-11-01

Source baseline: `a4bf518b5e58a69ecde6da194299417459a70b59` on `main`.

This batch corrects output failure reporting, playback handover, node synchronization and browser control ownership. It also strengthens qualification evidence and clean-checkout dependency preparation. It is software engineering evidence, not physical board qualification or a conformity assessment.

## Changes and resulting behavior

| Area | Reproduced problem | Correction |
| --- | --- | --- |
| PWM output gate | A rejected GPIO write could still report output enabled or inhibited | Gate operations return their errors, retain the last successfully commanded enable state and expose `output_gate_failed`; successful ordinary writes cannot clear that fault |
| Recovery and stop | An older recovery could acknowledge a newer gate failure; blackout, stop reset and topology publication could overlook failed inhibition | Gate-fault generations preserve newer failures. Zero frames are still attempted, while failed inhibition blocks a confirmed blackout, stop reset or replacement topology |
| I2C recovery | Failed driver deletion or GPIO operations could be ignored while recovery manipulated the bus | Driver ownership survives failed deletion. Recovery checks GPIO configuration, clock and STOP operations, and released-line observations before continuing |
| Scene continuity | A new timed scene could inherit a previous frozen/manual transition and remain at progress zero | New timed, immediate, manual and fallback playback establish their own transition mode; frozen state no longer leaks into the replacement |
| Sync takeover | Auto election could precede remote cue/scheduler cleanup, and failed timeout cleanup was discarded | The worker must acknowledge remote release before local leadership. Rejected cleanup retains diagnostics and retries; a valid packet at timer zero expires correctly; expired peer slots are reusable |
| Embedded dashboard | A permanent Connected label and cached status could conceal loss; failed resource reads replaced valid data with defaults | Owned WebSocket reconnects, bounded HTTP fallback, request deadlines, explicit freshness states and preserved loaded documents replace those failure paths |
| Editing and node selection | Initial scene loading and asynchronous operations could use incomplete data or a later selected node | Creation and saves require their source data; operations belong to the connection and node where they started, including restore, update and stop continuations |
| Dashboard telemetry | Safety/protocol labels and power budgets contained fixed values; previews could look like measurements | Existing runtime fields drive status, faults and configured budget. Missing estimates remain unavailable; preview rates and software power estimates are labelled explicitly |
| Browser persistence | Denied browser storage could throw during auth construction or fleet reads | A shared guarded boundary handles storage getters and operations. Session credentials remain tab-scoped, with in-memory operation when persistence is unavailable |
| Qualification records | Current file hashes were reported without comparing archived digests; checks only repeated firmware and board revision | Version 2 binds every result to the full declared build/unit/setup identity and compares each capture against its recorded SHA-256 |

The embedded interface retains the existing navigation and uses LumiGrid's cherry/pink palette. Its header distinguishes live updates, HTTP polling, reconnecting and offline state. A preserved value from a disconnected node is not displayed as a current measurement.

Embedded sessions now store the selected host and token together. Existing split host/token sessions require a fresh sign-in; the saved host preference is retained. Switching nodes cancels pending requests and prevents restore, upload, polling or stop continuations from targeting a subsequently selected node.

## Reproducible dependency preparation

The checked-in cJSON package contains 165 files, while its locked registry archive contains 234. The 69 omitted files are 68 upstream test files hidden by an upstream ignore rule and a regular `cJSON/.git` pointer file. That pointer participates in the registry hash but cannot be represented as a normal Git tree entry. All existing files were byte-identical to the registry package.

A clean checkout therefore failed the component manager's integrity gate before firmware compilation. Dependency preparation recognizes only that exact incomplete tree, checks its existing lock/marker identity and preserves it in a unique `.pio/dependency-snapshots/` backup. The normal component manager restores the locked package. Configuration then explicitly verifies the complete package hash before accepting it. Modified or unfamiliar local trees are left untouched and remain subject to normal integrity checks.

The dependency lock is unchanged. The expected complete cJSON component hash is `e788323270d90738662d66fffa910bfe1fba019bba087f01557e70c40485b469`. Integrity bypass settings are not used.

## Qualification record migration

Use [the updated evidence procedure](CONTINUITY_QUALIFICATION.md) and `evidence-template.json`. Version 1 records and plain evidence-path strings are rejected. A current digest cannot establish that an old test used the current specimen, wiring, supply or load. Preserve archived records and mark unverifiable checks `NOT_RUN` until repeated.

The tool checks supplied declarations, file identity and completeness. It does not independently verify measurements, approve electrical limits or issue a CE certificate.

## Remaining measured acceptance

Run the final factory image on the intended PCB, supply, loads, wiring, enclosure and antenna. Retain image identity and observations for these changed paths:

1. Observe output-enable and PWM behavior through boot, stop, clear and controlled I2C recovery. A successful GPIO API result describes the commanded state; actual pin level and output darkness require measurement.
2. Freeze a transition, then request a timed scene, a saved preset and fallback playback. Confirm the replacement advances and the previous manual/frozen controls do not persist.
3. Lose the sync leader during cue and timeline playback. Confirm ownership release precedes takeover; retain both nodes' logs and test recovery after rejected cleanup.
4. Exercise browser disconnect/reconnect and switching between nodes during pending operations. Confirm stale values are marked, loaded scenes remain intact and follow-up commands stay with their original node or are cancelled.
5. Complete loaded endurance, reset, memory/stack, current, temperature and the agreed radio/EMC/electrical assessment. No such physical measurements were taken in this batch.

One known modeling issue remains: `OutputController::enforce_power_guard_locked()` and `PowerBudget::enforce()` use different RGB/RGBW estimates, and the final guard scales its fixed-idle bookkeeping. For full RGB white their formulas currently yield 890 versus 300 mW per pixel; full RGBW yields 1,270 versus 385 mW. These are code-derived estimates, not measured current. Agree a shared model and reconcile post-guard telemetry against actual loads before using these estimates as an installation limit.
