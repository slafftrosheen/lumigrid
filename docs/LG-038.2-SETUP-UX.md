# LG-038.2 implementation and validation

FactoryFirstBoot now uses `LumiGrid-Setup` and the temporary Wi-Fi/setup
credential `lumigrid123`. Permanent AuthStore credentials still require
16–64 characters. Temporary sessions carry explicit restricted authority;
normal APIs, WebSocket tickets, networking, OTA, restore and credential
management require a provisioned node.

`POST /api/v1/auth/bootstrap` saves the permanent Admin key, revokes temporary
sessions and returns a new Admin session in the same request. NVS backup and
commit errors are propagated. Invalid existing auth storage fails closed
instead of being interpreted as first boot. Legacy migration never imports
the temporary setup value as a permanent account.

Both dashboards detect first setup, request a new confirmed Admin key and
continue directly into setup. Both offer key generation and Access account
management without displaying saved secrets. The embedded dashboard's
existing WebSocket callback had a missing closure that prevented its whole
script from executing; that syntax error is fixed.

## Automated evidence

- Dashboard unit suite: 382 tests passed.
- Browser regressions: six tests passed against mocked node APIs, exercising
  both real dashboards, confirmation, direct session entry, normal login,
  recovery gating, visible setup instructions and embedded role management.
- Svelte/copy checks: zero errors and zero warnings.
- Firmware factory and runtime-test images compile successfully.
- Architectural invariants and production boot-stack checks pass.
- Runtime A–J credential regressions are included in RuntimeHardeningTests.
  They exercise restricted setup sessions, permanent credential rejection,
  immediate revocation, NVS-backed manager reconstruction and explicit reset.

Run browser coverage with:

```powershell
cd lumigrid-lander-main
npx playwright test tests/e2e/first-setup.spec.ts --workers=1
```

The tests accept `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` when an existing local
Chromium installation is used instead of the version expected by Playwright.

## Physical acceptance remaining

No controller was flashed or reset during this change. Runtime assertions
were compiled, not executed on hardware. Actual first power-on, Wi-Fi change,
physical full reset and OTA rollback acceptance remain to be verified on a
test controller. Browser API fixtures and reconstructed AuthManagers do not
constitute that physical evidence.

Production flash usage remains near the current partition limit (about 99%).
