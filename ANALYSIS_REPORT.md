# LumiGrid Repository Analysis Report

This document outlines inconsistencies, placeholder assets, bad coding practices, and content mismatches discovered during a deep dive into the `LumiGrid` monorepo.

## 1. Inconsistent Information

*   **Repository Structure Misalignment:** The root `README.md` states `LED Node Firmware is maintained in a separate repository: ../Documents/LumigridLedNode/`. However, the firmware is actually located in the `LumigridLedNode/` directory *within* this monorepo.
*   **Implementation Status Mismatch:** The file `LumigridLedNode/PLAN.txt` lists "Physical button / emergency stop" and "Temperature / health monitoring" as "Missing". However, checking `LumigridLedNode/usermods/lumigrid_pca9685/usermod_lumigrid_pca9685.cpp` reveals that these features are actively implemented.
*   **Time Traveler Documentation:** The `lumigrid-lander-main/AUDIT_SUMMARY.md` file is marked with a date in the future (`2026-01-08`).

## 2. Placeholder Functionality

Multiple assets and files are non-functional placeholders:

*   **Fake Assets:**
    *   `lumigrid-lander-main/static/assets/downloads/product-sheet.pdf` is not a valid PDF file. It is a plain text file containing the string `Product sheet placeholder`.
    *   `lumigrid-lander-main/static/assets/press/logo-horizontal.svg` is not a valid SVG file. It contains the string `Logo placeholder`.
*   **UI / Frontend Placeholders:**
    *   Several components (e.g., `SignageAssetBoard.svelte`, `WhiteOnlyDemo.svelte`) contain explicit mentions of "placeholder".
*   **Configuration Placeholders:**
    *   `lumigrid-lander-main/README.md` states that `ali-deploy.sh` contains placeholder values that need to be replaced with actual Alibaba Cloud details.

## 3. Bad Coding Practices & Rule Violations

*   **AI Agent Rule Violations (`AGENTS.md`):**
    *   The files `usermods/lumigrid_content_scheduler/usermod_lumigrid_content_scheduler.cpp` and `usermods/lumigrid_telemetry/usermod_lumigrid_telemetry.cpp` are entirely wrapped in `// AI: below section was generated by an AI` comments. However, they violate the `AGENTS.md` directive which requires: *"Every non-trivial AI-generated function should have a brief comment describing what it does. Explain parameters... AI-generated code must be well documented with meaningful comments"*. There are no such explanatory comments in these files.
*   **Memory Management & Thread Safety Issues (ESP32):**
    *   In `usermods/lumigrid_telemetry/usermod_lumigrid_telemetry.cpp`, a string is dynamically allocated (`String* url = new String(heartbeatUrl);`) and passed to an ESP32 FreeRTOS task (`heartbeatTask`). If `xTaskCreate` fails to create the task, the task never runs and the allocated string is never deleted, leading to a memory leak.
    *   Furthermore, frequent dynamic allocations/deallocations of `String` objects on the heap lead to heap fragmentation, which is explicitly discouraged for long-running embedded devices in `AGENTS.md`.
*   **Poor DOM Manipulation in SvelteKit:**
    *   In `lumigrid-lander-main/src/lib/components/BackgroundFlare.svelte`, a `dummy` div is manually created via `document.createElement('div')`, appended to `document.body` to read a computed CSS variable, and then removed. This is an anti-pattern in modern frontend frameworks like SvelteKit, which should manage the DOM directly.

## 4. Content and Branding Mismatches

*   **Company vs. Domain Mismatch:** The `README.md` states that "LumiGrid is built by Reclame Fabriek". However, internal references and deployment URLs (such as those in `PLAN.txt`) point to `algorhythmicdev.github.io/lumigrid-lander/`, indicating a discrepancy between the stated brand and the actual deployment infrastructure.
